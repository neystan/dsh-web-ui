# Skin Center 第 11 个自定义主题设计

## 状态

本设计已确认。自定义主题是与 10 个内置皮肤并列的第 11 个主题；官方默认保持纯净且独立。试穿不刷新页面，应用沿用内置皮肤的持久化、确认和刷新流程。

## 目标

- 自定义主题使用与内置皮肤相同的卡片、激活徽标、试穿和应用状态机。
- 自定义主题额外提供编辑入口，支持亮色、暗色的强调色、背景色、前景色和对比度。
- 自定义主题可在刷新和 DSH 重启后独立恢复，不依赖打开设置页面。
- 官方默认、自定义主题和 10 个内置皮肤互斥激活。
- 全局背景图片继续作用于当前任意主题。

## 不做的功能

- 不动态生成或执行用户提供的皮肤 bundle、CSS 或 JavaScript。
- 不允许修改字体、圆角、间距或任意底层 token。
- 不增加多套自定义主题、主题导入导出、主题市场或每主题独立背景。
- 不改变内置皮肤包自身的实现。
- 不取消应用后的页面刷新。

## 主题身份和数据模型

UI 中的主题身份分为 `official`、`custom` 和 10 个生成注册表条目。标题计数为 11，只统计 10 个内置皮肤和自定义主题；官方默认是独立恢复入口，不计入皮肤数量。

`skin-custom-theme` 设置增加独立激活字段：

```ts
interface CustomThemeSettings {
  version: 2
  active: boolean
  light?: PaletteConfig
  dark?: PaletteConfig
}

interface PaletteConfig {
  accent: string
  background: string
  foreground: string
  contrast: number
}
```

版本 1 配置迁移时保留亮暗参数；存在任一有效亮暗参数则迁移为 `active=true`，两套参数都不存在则为 `active=false`。内置皮肤仍按启动清单优先，因此迁移不会把颜色泄漏到内置皮肤。非法或未知配置回退到未激活状态，不阻止 Web GUI 启动。

当前主题按以下唯一顺序判定：

1. 启动清单包含内置皮肤包时，该内置皮肤激活，自定义字段不影响页面。
2. 启动清单没有内置皮肤且 `active=true` 时，自定义主题激活。
3. 启动清单没有内置皮肤且 `active=false` 时，官方默认激活。

切换到官方或内置皮肤只关闭自定义主题，不删除用户的颜色参数。再次应用自定义主题时恢复原参数。

## 统一卡片和操作

官方、自定义和内置皮肤复用同一个卡片渲染函数及同一套按钮、禁用、错误、试穿中和当前激活样式。

内置皮肤卡保持“试穿 / 应用”。自定义主题卡显示“试穿 / 应用 / 编辑”。官方默认卡只显示“试穿 / 恢复默认”，不再承载“自定义 / 已自定义”按钮。

编辑界面沿用现有颜色行、滑块、按钮、间距和语义色。背景编辑器仍是皮肤中心的全局区域，也可在自定义编辑界面内复用，但设置只有一份。

## 试穿生命周期

所有主题的试穿均不写设置、不写启动补丁、不刷新页面，并通过现有 `TryOnController` 进入和退出。

试穿内置皮肤继续加载真实 client bundle。试穿官方默认继续临时撤下当前内置皮肤及外观层。

试穿自定义主题采用同一表面切换生命周期：控制器先撤下当前内置皮肤或官方表面，再在官方基础表面临时启用已保存的自定义颜色和全局背景。退出时先移除临时自定义变量，再恢复进入前的皮肤属性、DOM、背景、亮暗模式和自定义激活状态。

编辑自定义主题等价于进入自定义试穿会话。实时预览只修改受控语义变量；取消恢复进入编辑前的主题和参数；点击“保存并应用”先持久化参数，再进入自定义主题的统一应用流程。

`TryOnController` 和外观控制器通过明确的 `beforeSurfaceChange`、`afterSurfaceChange`、`afterExit` 生命周期协调，不快照或清空整个 `body.style`。

## 应用生命周期

应用保持现有内置皮肤方法：写入目标状态，POST `/api/skin-center/apply`，轮询 `/api/skin-center/state`，确认启动清单，最后调用 `window.location.reload()`。

不同主题只在持久化目标上有必要差异：

- 应用内置皮肤：先持久化 `active=false`，再提交 `{ skin: id }`。
- 应用官方默认：先持久化 `active=false`，再提交 `{ official: true }`。
- 应用自定义主题：确保至少存在官方近似预设，持久化 `active=true`，再提交 `{ official: true }`。

自定义主题因此使用官方启动图作为安全基础，但在产品状态和启动恢复上是独立主题，而不是官方卡的附属功能。

设置写入或 `/apply` 失败时恢复应用前的 `active` 值，保留当前试穿表面并显示稳定错误；状态或清单确认超时则不刷新，并显示现有命令回退提示。

## 自定义参数和恢复默认

每种亮暗模式只编辑四项：强调色、背景色、前景色和对比度。颜色固定为 `#RRGGBB`，对比度为 `0` 至 `100` 的整数。

“恢复默认参数”把亮色和暗色同时写为固定的官方近似预设，并立即预览；它不关闭 `active`，也不切换到官方默认主题。官方默认预设由测试锁定，避免依赖浏览器在某一时刻计算出的样式。

颜色仍由纯函数派生到集中 allowlist 中的 DSW 语义变量。控制器逐项保存并恢复原值和 priority，不接受用户变量名或原始 CSS。

## 启动恢复

`CustomThemeController` 在 client 插件应用时读取设置和启动清单。仅当没有内置皮肤且 `active=true` 时立即写入当前亮暗模式的语义变量；该过程早于设置卡片打开，设置 UI 是否挂载不影响主题生效。

亮暗模式变化时重新派生当前配置。控制器暂停、退出试穿、切换主题或销毁时逐项恢复原值，避免自定义颜色泄漏到其他主题。

## 背景

现有 `skin-background` 设置和图片存储保持全局唯一。跟随皮肤、自定义图片、无背景和遮挡滑块继续作用于当前官方、自定义或内置皮肤；自定义主题不保存专属图片。

表面切换时背景控制器沿用同一 suspend/resume 生命周期，在主题试穿退出和页面启动后重新应用当前全局模式。

### 自定义背景的可见合成

背景图片写在 `body` 的最底层。自定义主题无条件把现有 allowlist 中的基础层、内容层、侧栏、菜单、输入和气泡等受控语义表面派生为原有透明度的 RGBA；不新增全局选择器或强制覆盖。是否存在图片不改变 token，也不触发主题重新派生。`body` 另外写入当前亮暗配置的不透明背景色作为画布：有图片时它位于图片下方，无图片时为半透明表面提供稳定底色。

背景控制器不再发布主题协调属性，自定义主题只观察亮暗模式。暂停试穿或销毁时必须恢复进入前的 token 与 `body` 背景色。组合测试必须同时实例化真实背景和自定义主题控制器，断言有图和无图时关键表面 alpha 都小于 1、会话侧栏 token 半透明、底层画布不透明。

## 代码边界

- `core/theme.ts`：配置版本、迁移、官方近似预设和纯状态判定。
- `client/custom-theme.ts`：激活持久化、试穿预览、参数重置和受控变量生命周期。
- `client/try-on.ts`：为自定义表面提供与官方及内置皮肤一致的进入、退出协调点。
- `client/SkinCenter.tsx`：统一卡片渲染、目标状态和应用编排，删除官方卡中的自定义特殊分支。
- Host SettingsScope schema：接受版本 2 激活状态；现有背景 API 不变。

不新增动态 loader entry、协调器服务或第二套主题注册表。

## 测试和验收

纯逻辑测试覆盖版本 1 迁移、三类激活判定、官方近似预设、颜色派生和 token 白名单。

Client 测试覆盖：

- 自定义卡与 10 个内置卡使用相同状态和样式。
- 官方、自定义、内置皮肤互斥激活。
- 自定义试穿和退出不刷新、不写配置且完整恢复。
- 三种应用均经过写设置、`/apply`、状态确认、清单确认和刷新。
- 应用失败回滚激活字段且不刷新。
- 保存并应用、取消编辑、恢复默认参数和亮暗切换。
- 启动阶段自动应用自定义主题，不依赖设置卡片挂载。
- 全局背景在官方、自定义和全部内置皮肤间切换及试穿后保持正确。

手工验收至少覆盖 Edge 和应用内浏览器：试穿无刷新，应用仅刷新一次；刷新和重启后徽标、颜色、背景与启动主题一致。

## 构建和完成标准

更新 skin-center 测试及中英文 README，重新生成 client bundle，并构建 `packages/dsh-skins` 聚合产物。至少运行：

```text
pnpm --filter @neystan/dsh-client-ui-skin-center test
pnpm --filter @neystan/dsh-client-ui-skin-center typecheck
pnpm --filter @neystan/dsh-client-ui-skin-center build
pnpm skin-center:check
pnpm --filter @neystan/dsh-skins build
pnpm docs:check
```

完成标准是：自定义主题作为独立第 11 个主题工作；具体卡片、试穿和应用方法与原主题一致；试穿不刷新，应用刷新；官方默认不带自定义效果；全局背景在所有主题中保持一致；无效设置或失败操作不阻止 Web GUI 启动。
